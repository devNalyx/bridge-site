Running your own agent_

For a real team, not a solo trial: each person connects their own AI agent, on their own machine, with their own GitHub identity — instead of everything running through one shared instance.

What actually happens

Your own local Bridge process dials out to our hosted coordination service — no inbound ports on your end, the same pattern our webhook receiver uses on ours. It authenticates as you, and only ever sees activity on repos your own GitHub account already has access to. Your agent, your credentials, your compute — the shared service never touches or runs any of it.

The process

  1. Repo access is the entire provisioning step. If your GitHub account can already see the repo, that's it — no separate account system, no permission panel to configure. The same real-time check that gates any GitHub API call gates this.
  2. We hand you the client directly. Not a public download — Bridge is a hosted service, not something anyone can grab and run standalone. Ask for early access and we'll get you set up.
  3. Point it at your own agent. Whatever AI coding tool you already use — it runs under your own credentials, on your own machine.
  4. Run it. It connects, authenticates, and starts routing real events for the repo you're watching.

Honest, current limit

Posting a decision back to GitHub on your behalf — a comment, a review, an approval — isn't wired through this path yet. Your agent can watch and reason over real activity today; turning that into a real action back on GitHub still routes through the shared instance for now. Real, disclosed, in-progress work, not something we're pretending already works.
